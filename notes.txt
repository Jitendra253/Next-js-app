->Server side scripting vs client side scripting
    ->Client-side scripting executes in the user's browser and is mainly responsible for UI and user interactions. Server-side scripting executes on the server and handles business logic, authentication, API processing, and database operations. React is primarily client-side, while Node.js is server-side.

    -Next.js supports both server and client execution. By default, components in the App Router are Server Components, which execute on the server. When we add 'use client', the component becomes a Client Component and can use browser APIs and interactive React features such as useState and event handlers. SSR refers specifically to rendering HTML on the server, while Server Components refer to where the React component code executes.

*Rendering in Next js:
-----------------------
->What is rendering?
    ->Rendering means converting your React components into HTML that can be displayed in the browser.
->Rendering Environments.
     ->Rendering environments in Next.js refer to the environments where components are executed and rendered. Next.js primarily uses the server environment for Server Components and the browser/client environment for Client Components.

->Component-level client and Server Rendering
    ->Component-level client and server rendering in Next.js means individual components can be rendered in different environments. Components are Server Components by default, while "use client" makes a component a Client Component. This allows Next.js to keep most of the application on the server while sending JavaScript only for interactive components.
->What is Pre-rendering?
    ->Pre-rendering means generating the HTML of a page before it is sent to the browser.
    ->Instead of making the browser create everything using JavaScript, Next.js can prepare the HTML in advance and send it to the user.
->Static Generation?
    ->Static Generation is a pre-rendering technique where Next.js generates the HTML of a page ahead of time, typically during the build process. The generated HTML can then be served quickly to users without rendering the page again for every request.
->Server-side rendering?
    ->Server-Side Rendering (SSR) is a rendering technique where Next.js generates the HTML for a page on the server for each request and sends the generated HTML to the browser. It is useful for dynamic or request-specific content and can provide good SEO and fast initial HTML delivery.

*Next.js mainly supports these rendering approaches:
----------------------------------------------------
    ->1.Static Rendering (SSG)
            HTML is generated ahead of time.
            Usually very fast.
            Good for pages whose content doesn't change frequently.
    ->2.Dynamic Rendering (SSR)
            HTML is generated on the server when a request comes in.
            Useful for data that changes frequently or depends on the request.
    ->3.Client-side Rendering (CSR)
            JavaScript runs in the browser and generates/updates the UI.
            Used with Client Components ("use client").
    ->4.Streaming
            Next.js can send parts of the UI to the browser as they become ready instead of waiting for the entire
